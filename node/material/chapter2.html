What is Node.js?

Understanding what Node.js really is, how it works, and what it lets us build.

The Big Picture

What is a server?

A server is just a computer that listens for requests and sends back responses — 24/7, without a screen or keyboard.

When you visit a website, your browser sends an HTTP request to a server. The server sends back HTML, CSS, and JavaScript.

A server can be a physical machine in a data centre, or a virtual machine in the cloud — same idea, different packaging.

Back End

When do you actually need a back end?

You need one when…

  • Users can log in with accounts
  • Data changes and must be stored (posts, orders)
  • Pages show different content per user
  • You're building an API for other apps
  • You need to send emails or notifications

You don't need one when…

  • It's a portfolio or brochure site
  • Content is fixed and doesn't change
  • No user accounts or personalisation needed
  • A static site generator can handle it

Node.js — nodejs.org

What Node.js actually is

Node.js is an open-source, cross-platform JavaScript runtime environment — it lets you run JavaScript outside the browser.

It runs on the V8 engine — the same engine that powers Google Chrome. This makes it very fast.

Before Node.js (created in 2009), JavaScript could only run inside a browser. Node freed it to run on servers too.

In short: Node.js is the thing that lets your JavaScript code run on a server, not just in a browser tab.

How Node.js Works

Synchronous vs Asynchronous

Synchronous

Tasks run one at a time, in order. The next task waits until the current one is fully done.

Like a single cashier who can only serve one customer at a time — everyone else must wait in line.

Asynchronous

Tasks are started and left to run in the background. Node moves on and comes back when each task is ready.

Like placing an order at a restaurant — the kitchen works on it while you wait, not while everyone else watches.

How Node.js Works

The event loop

Node.js runs in a single process — it doesn't create a new thread for every request.

Instead it uses an event loop: it starts tasks (read a file, query a database), then waits for whichever finishes first.

When a task finishes, Node fires an event and runs the callback function you gave it. No wasted waiting.

This lets Node handle thousands of connections at once on a single server — without the complexity of managing multiple threads.

The Event Loop — Example

Two tasks running at the same time

Node starts reading a file and simultaneously starts a database query. Both run in the background.

Node sits and waits. Whichever task finishes first fires an event — Node runs its callback immediately.

As programmers, we don't need to know or care which order they finish — Node handles it.

If this were synchronous, we'd wait for the file to finish before the database query could even start — much slower.

Node.js in Practice

Your first Node.js server

const http = require('http'); http.createServer(function(req, res) { res.writeHead(200, { 'Content-Type': 'text/html' }); res.end('Hello World!'); }).listen(8080); // "Any time we get a network request, run this function." // Visit http://localhost:8080 — you'll see: Hello World!

This is a real, working web server in about 5 lines. Node handles the HTTP layer — you just write the logic.

Node.js in Practice

What can you build with Node.js?

REST APIs — provide data to front-end apps or mobile apps (JSON responses).

Full-stack web apps — serve HTML pages and handle user data, login, forms.

Real-time apps — chat apps, live notifications (Node's event model is great for this).

Command-line tools — scripts and automation that run on your machine, not a browser.
