Part 1

Running Node.js

Two ways to execute JavaScript outside the browser

Running Node.js

Running a JavaScript file with Node

Create a file — e.g. app.js — and write any JavaScript inside it.

In your terminal, run it with: node app.js

Node reads the file top to bottom, executes every line, then exits. That's it.

// app.js const name = 'Node.js'; console.log(`Hello from ${name}!`); // terminal: node app.js // output: Hello from Node.js!

The REPL

Read – Eval – Print – Loop

Type node in the terminal with no file — you get an interactive prompt. Perfect for quick experiments.

Node reads your input, evaluates it, prints the result, then loops back waiting for more.

Unlike the browser console, the REPL prints the return value of every expression automatically.

node — REPL
$node
>5 + 3
8
>console.log('hello')
hello
undefined
>.exit

The REPL is great for testing small functions or checking syntax before putting it in a real file. Use it often.

Part 2

Modules

How Node.js organises and shares code between files

Modules

What is a module?

A module is just a JavaScript file. Every file in Node.js is its own module with its own scope.

Variables and functions defined in a file are private by default — other files can't see them unless you explicitly export them.

You export things with module.exports, and import them with require().

math.js — exporting
function add(a, b) { return a + b; } function subtract(a, b) { return a - b; } module.exports = { add, subtract };
app.js — importing
const math = require('./math'); console.log(math.add(2, 3)); // → 5 console.log(math.subtract(9, 4)); // → 5

Modules

Three types of modules in Node.js

Built-in

Come with Node.js — no installation needed. Just require() them by name.

const fs = require('fs'); const http = require('http'); const path = require('path');

Your own

Files you create. Use a relative path starting with ./ so Node knows it's a local file.

const math = require('./math'); const db = require('./db');

Third-party

Installed from NPM. Live in node_modules/. Just require by package name.

const express = require('express'); const lodash = require('lodash');

No ./ → built-in or node_modules.   With ./ → your own file. That's how Node decides where to look.

Part 3

The HTTP Module

Building a web server with Node's built-in http module

HTTP Module

Your first web server in Node.js

const http = require('http'); const server = http.createServer(function(req, res) { res.writeHead(200, { 'Content-Type': 'text/html' }); res.end('<h1>Hello World</h1>'); }); server.listen(3000, () => { console.log('Server running at http://localhost:3000'); });

createServer() takes a callback. That callback fires on every incoming request.

req — the incoming request (URL, method, headers).   res — what we send back.

listen(port) — tells the server which port to watch. Visit localhost:3000 in the browser to see it.

HTTP Module

The req and res objects

req — the request

Contains everything about the incoming request.

req.url // e.g. '/about' req.method // 'GET', 'POST'… req.headers // object of headers

Use req.url to route different paths to different responses.

res — the response

How you send data back to the browser.

res.writeHead(200, { 'Content-Type': 'text/html' }); res.end('<p>Response body</p>');

Always call res.end() — it signals that the response is complete.

The URL Module

Parsing and reading the parts of a URL

URL Module

Splitting a URL into readable parts

const url = require('url'); const addr = 'http://localhost:3000/page?year=2024&month=July'; const parsed = url.parse(addr, true); console.log(parsed.host); // localhost:3000 console.log(parsed.pathname); // /page console.log(parsed.query); // { year: '2024', month: 'July' } console.log(parsed.query.year); // 2024

Part 5

The fs Module

Reading, writing, updating and deleting files

File System (fs)

Reading and writing files

Reading a file
const fs = require('fs'); fs.readFile('hello.txt', 'utf8', function(err, data) { if (err) throw err; console.log(data); } );
Writing a file
const fs = require('fs'); fs.writeFile('hello.txt', 'Hello, Node!', function(err) { if (err) throw err; console.log('File saved!'); } );

Both are asynchronous — they take a callback that runs when the operation finishes. The rest of your code keeps running in the meantime.

File System (fs)

Appending, renaming and deleting files

Append to a file
fs.appendFile( 'log.txt', 'new line\n', function(err) { if (err) throw err; console.log('Done'); } );
Rename a file
fs.rename( 'old.txt', 'new.txt', function(err) { if (err) throw err; console.log('Renamed'); } );
Delete a file
fs.unlink( 'file.txt', function(err) { if (err) throw err; console.log('Deleted'); } );
Method
What it does
fs.readFile()
Read the contents of a file
fs.writeFile()
Create or overwrite a file with new content
fs.appendFile()
Add content to the end of a file
fs.rename()
Rename (or move) a file
fs.unlink()
Delete a file
Part 6

NPM

Node Package Manager — install, manage and share code

NPM

What is NPM and why do we need it?

NPM is the package manager for Node.js. It comes installed with Node automatically.

It lets you install third-party libraries (packages) written by other developers so you don't reinvent the wheel.

It also manages your project's dependencies — a list of every package your project relies on, saved in package.json.

The npm registry at npmjs.com hosts over 2 million packages. Anything you can think of probably already exists.

NPM

package.json — the heart of every Node project

{ "name": "my-app", "version": "1.0.0", "description": "My first app", "main": "index.js", "scripts": { "start": "node index.js" }, "dependencies": { "express": "^4.18.0" }, "devDependencies": { "nodemon": "^3.0.0" } }

name / version — identifies your project.

scripts — shortcuts you can run with npm run start.

dependencies — packages your app needs in production.

devDependencies — packages only needed during development (e.g. testing tools).

NPM

Always add node_modules/ to your .gitignore file — it can be hundreds of MB. Anyone can recreate it by running npm install.

Part 7

Events

Creating, firing and listening for custom events

Events

Node's EventEmitter class

Node.js has a built-in events module. At its core is the EventEmitter class.

You can create an EventEmitter, listen for named events with .on(), and fire them with .emit().

This is the same pattern used internally throughout Node — http servers, file streams, and more all emit events.

const EventEmitter = require('events'); const emitter = new EventEmitter(); // Register a listener for the 'greet' event emitter.on('greet', function(name) { console.log(`Hello, ${name}!`); }); // Fire the event, passing data along emitter.emit('greet', 'World'); // → Hello, World! emitter.emit('greet', 'Node'); // → Hello, Node!

Events

Key EventEmitter methods

Method
What it does
.on(event, fn)
Listen for an event — fires every time it's emitted
.once(event, fn)
Listen once — automatically removed after first fire
.emit(event, ...args)
Fire an event, optionally passing data to listeners
.removeListener()
Remove a specific listener from an event
.removeAllListeners()
Remove all listeners (optionally for one event)

The EventEmitter pattern is used throughout Node's own internals. When you do server.on('request', ...) on an HTTP server, that's EventEmitter under the hood.
